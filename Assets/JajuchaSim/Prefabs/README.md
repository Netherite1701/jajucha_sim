# Prefab ownership (Step 11.30/11.31)

This folder contains the **authoritative prefab templates** for the
simulator. The design principle (DD-022): **avoid duplicated slightly
different prefab copies** — one authoritative source per object.

The prefab assets here are generated by `tools/generate_prefabs.py` (a
build-time helper, same approach as `tools/generate_scene.py`). The runtime
still builds the vehicle/course procedurally; the prefabs exist so the project
has exactly one authoritative definition per object and no hand-duplicated
copies anywhere.

## Core

- `Core/SimulatorCore.prefab` — the `_Core` group template
  (`SimulationManager` + `SimulationDebugHud` + `SimulationRunner` +
  `ApplicationBootstrap`). The authoritative scene
  `Assets/JajuchaSim/Scenes/JajuchaSimulator.unity` wires these nodes
  directly and is validated by `SceneHierarchyValidationTests`.

## Vehicle

- `Vehicle/JajuchaVehicle.prefab` — the authoritative vehicle template
  (Step 11.31):

  ```text
  JajuchaVehicle
  ├─ chassis visual          (Chassis: cube mesh + BoxCollider)
  ├─ collision body          (Chassis BoxCollider; root Rigidbody)
  ├─ front-left steering/wheel  (FL_Wheel)
  ├─ front-right steering/wheel (FR_Wheel)
  ├─ rear-left wheel            (RL_Wheel)
  ├─ rear-right wheel           (RR_Wheel)
  ├─ sensor mounts
  │  ├─ left camera             (LeftCamera)
  │  ├─ center camera           (CenterCamera)
  │  └─ right camera            (RightCamera)
  └─ debug anchors           (DebugAnchors)
  ```

  All root transforms are identity (position 0,0,0 / rotation 0 / scale 1).
  `VehicleSystemBehaviour` re-applies the tuned `WheelCollider` physics
  (spring, friction, radius) to the wheel nodes at runtime from one
  `VehicleConfig` (see `VehicleSystem.CreateWheel`), so the prefab keeps the
  hierarchy + visuals while physics tuning stays in one place.

## UI

- `UI/RuntimeUI.prefab` — the runtime UI group template (`MapEditorHud` root
  + panel nodes). Panels are built programmatically at runtime by
  `SimulationDebugHud`, `MapEditorHud`, `ScenarioPanel`, and
  `RuntimeStatusBar` so they work identically in the standalone build.

## Course

- `Course/CourseRuntimeRoot.prefab` — the course runtime root template
  (empty `CourseRuntimeRoot` + `RoadLayerRoot`/`StructureLayerRoot`/
  `ObjectLayerRoot`/`TriggerLayerRoot`/`RuntimeOverlayRoot`). Runtime course
  objects are generated under these roots by `CourseOverlayRenderer` +
  `StructureMeshBuilder` from the loaded course document (course-data
  authority, DD-017).

## Objects

- `Objects/Obstacle.prefab` — obstacle template (cube + BoxCollider).
- `Objects/SlowSign.prefab` — slow-sign template.
- `Objects/StartSignal.prefab` — start-signal template.
- `Objects/SpeedTerminal.prefab` — speed-terminal template.

Object geometry is generated by `StructureMeshBuilder` / overlay renderers
from `CourseDocument` features; these prefabs are the authoritative templates
for those object kinds.

> Regenerate with: `python tools/generate_prefabs.py`
> (writes the 8 prefab files; `.meta` GUIDs are fixed and committed).

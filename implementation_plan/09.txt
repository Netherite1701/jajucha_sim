Step 8 — Scenario, Timing, and Scoring System
This step turns the simulator from “a car driving on a map” into an actual competition/test environment.
The important rule is:
The simulator knows the ground truth for scoring, but the autonomous-driving code does not.
So Unity can know that the car entered a slow zone, crossed a gate, hit an obstacle, or finished the course. Python still has to infer what is happening from the simulated cameras and jchm interface.

8.1 End goal
A complete run should work like:
Reset
  ↓
Waiting for start
  ↓
Start signal activates
  ↓
Timer starts
  ↓
Car drives
  ↓
Slow zone measured
  ↓
Obstacle collisions tracked
  ↓
Speed gates measured
  ↓
Finish crossed
  ↓
Run ends
  ↓
Results displayed

And all of this must work in the standalone build.

8.4 ScenarioManager
Responsibilities:
prepare run
control scenario state
start/stop timer
listen to course events
send events to scoring rules
finalize results

It should not:
drive the car
run ANN
run FSM
render cameras
edit the map


8.5 ScenarioDefinition
Course geometry and scenario rules should remain separate.
Example:
{
  "scenario": {
    "name": "Competition Run",

    "startTrigger": "start_line",
    "finishTrigger": "finish_line",

    "maxRunTimeSec": 180,

    "slowZones": [
      {
        "triggerId": "slow_zone_01",
        "maxSpeedCmS": 20
      }
    ]
  }
}

This means the same course could theoretically be tested with different rules.

8.10 Run timer
The official simulation timer should use:

not wall-clock time.
Therefore at:

2×
8×

8.13 Slow zone rule
Step 7 already provides:
SlowZoneEntered
SlowZoneExited

Now Step 8 evaluates vehicle speed while inside.
Example:
slow_zone_01

max allowed speed:
20 cm/s

Track:
entry time
exit time
maximum speed
average speed
time above limit


8.14 Don't score using jchm speed command
Important distinction:
jchm.control speed = 3

is a motor command.
Actual speed might differ.
Scoring must use:
actual simulated vehicle velocity

from ground truth.
So:
vehicle speed = Rigidbody-derived cm/s

is what SlowZoneRule evaluates.

8.15 Slow-zone measurement
At each simulation tick while inside:
currentSpeed = vehicle.ForwardSpeedCmS

update:
maxSpeed
sum / average
timeAboveLimit

Then on exit generate result.
Example:
slow_zone_01

Allowed:     ≤20.0 cm/s
Maximum:      23.4 cm/s
Average:      17.2 cm/s
Over limit:    0.31 s

Result: FAIL

Support:

8.17 Collision tracking
The simulator should detect collisions with:
obstacles
tunnel walls
course structures

but not count ordinary:
wheel-road contact

as collisions.
Use collision categories/layers.

8.18 Collision event
Vehicle collision system publishes:
VehicleCollisionEvent
{
    objectId
    relativeVelocity
    simulationTime
}

Scenario system records it.

8.19 Collision debouncing
A car resting against one obstacle may generate many physics callbacks.
Don't count:
50 collision callbacks

as:
50 crashes

Use per-object collision sessions:
collision begins
→ one incident

remain touching
→ no new incident

separate
→ collision session ends

8.24 Start-line crossing vs green light
These are different things.

Option A

Option B

For initial implementation, I'd support:
StartTimingMode.SignalGreen

8.37 Student code still unchanged
Student autonomous program still only sees:
import jchm

image = jchm.camera.get_image("center")
...
jchm.control.set_motor(...)

It should not call:
jchm_sim.get_result()

during normal autonomous logic.
That's for test harnesses.

8.38 Automated run flow
Now an external test script can do:
import jchm_sim

jchm_sim.reset()
jchm_sim.start_run()

# launch autonomous code

result = jchm_sim.wait_for_result()

Later agentic coding can use this.

8.39 Don't make wait_for_result() infinite
Give timeout support:
result = jchm_sim.wait_for_result(
    timeout=180
)

or poll status.

8.40 Scoring engine design
Keep scoring rules modular:
IRunRule
├─ OnRunStart()
├─ OnEvent()
├─ OnTick()
└─ Finalize()

Examples:
SlowZoneRule
CollisionRule
FalseStartRule
CompletionRule
SpeedGateRule

This avoids one giant ScoreManager.cs.

8.41 Score should be optional
Some simulator sessions may just be development tests.
Scenario config:
ScoringEnabled = true/false

If false:
timing/events still work
no final points calculated
Useful during debugging.

8.42 Raw data first, points later
I recommend not hardcoding a competition points system yet.
Record:
time
speed
collisions
zone violations
completion

first.
Then when actual scoring rules are known, map those measurements to points.
That prevents us from inventing competition rules.

8.43 Generic penalties
We can support generic penalties without committing to exact values.
Example:
PenaltyRecord
{
    ruleId
    reason
    value
}

But scenario files define the actual numbers.

8.48 Reset semantics
jchm_sim.reset() now resets:
Scenario state → Ready
RunTimer → 0
ScoreManager → empty
Triggers → reset
Start signal → initial state
Vehicle → start pose
Simulation clock → 0

One deterministic reset.

8.49 Run Again
Results panel:
[ Run Again ]

should:
reset
→ ready
→ execute start sequence

No scene reload required.

8.50 Abort
Runtime:
[ Abort Run ]

sets:
ScenarioState.Aborted

stops vehicle propulsion for safety:
speed = 0

but does not destroy results collected so far.

8.51 Collision after finish
Once:
ScenarioState == Finished

new events should not alter the finalized result.
This avoids weird results if the car rolls into something after crossing finish.

8.52 Slow-zone overlapping triggers
If multiple slow zones overlap, track them independently by ID.
Don't use one global:
isInSlowZone

Use:
activeZones = Set<string>

or rule-local state.

8.53 Gate crossing direction
Speed gate should optionally require direction.
Example:
A → B

not count driving backwards through:
B → A

unless configured.
Store gate normal/orientation.

8.54 Finish direction
Same.
Finish line can optionally only count if crossed in the correct direction.
Useful if track loops near itself.

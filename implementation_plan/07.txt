Step 7 — Tile-Based Structures, Objects, and Trigger System
Now that the map is based on a single shared tile grid, Step 7 should add everything that sits on top of the road:
tunnels
ramps
obstacles
signs
start signals
slow zones
speed gates
event triggers
All of them use the same tile size and coordinate system as the road.

7.1 Core rule
Every feature is positioned through:
GridCoordinate(x, z)

or a rectangular region:
GridRegion
{
    x
    z
    width
    height
}

So if tile size is:
20 cm × 20 cm

then:
GridCoordinate(4, 7)

always maps to the same physical place for:
Road
Tunnel
Obstacle
Trigger
Sign

No separate snapping systems.

7.2 Shared map layers
Keep the map very simple:
CourseGrid
│
├─ Road Layer
├─ Structure Layer
├─ Object Layer
└─ Trigger Layer

Example:
cell (10, 8)

Road:
    Road

Structure:
    Tunnel

Object:
    none

Trigger:
    SlowZone

Layers may overlap.
That means a tunnel doesn't replace the road underneath it.

7.3 Data structure
Something roughly like:
public sealed class CourseCell
{
    public bool HasRoad;

    public StructureInstance Structure;

    public List<CourseObjectInstance> Objects;

    public List<TriggerInstance> Triggers;
}

But don't instantiate one heavy object per cell if the map becomes large.
The underlying grid can store IDs/references compactly.

7.4 Structures
Structures change the 3D course geometry.
Initially support only:
Tunnel
Ramp

Maybe later:
Bridge
Raised section
Wall

But don't add those yet.

Map Editor

│ T  │ T  │ T  │ T  │

The selected region defines the tunnel footprint.

7.7 Tunnel geometry generation
Generate:
left wall
right wall
roof

over the selected road cells.
Conceptually:
         roof
     ┌─────────────┐
     │             │
wall │    road     │ wall
     │             │
     └─────────────┘

The road underneath stays unchanged.

7.8 Tunnel orientation
For rectangular tunnel regions, orientation should derive from the region:
width < length
→ long axis = tunnel direction

or the user can rotate:
0°
90°

Don't make arbitrary free-angle tunnels initially.
Grid-aligned is enough.

7.9 Ramp
Ramp differs because it modifies the driving surface.
So instead of:
Road + structure overlay

the ramp should create a special surface over selected road tiles.
Workflow:
Structures
→ Ramp
→ select rectangular tile region
→ choose direction
→ enter height

7.12 Ramp geometry
The surface generator should calculate tile elevation across the ramp.
For example:
tile row 0 → 0 cm
tile row 1 → 5 cm
tile row 2 → 10 cm
...
tile row 6 → 30 cm

The road mesh for those tiles follows that elevation.
Later sections can continue flat at the raised level if needed, but for Step 7 keep ramps simple.

7.13 Objects
Objects do not modify road geometry.
Examples:
Obstacle
Sign
Start Signal

They occupy one or more grid cells.

7.14 Obstacle placement
Select:
Objects → Obstacle

Click a road tile:
┌────┐
│ O  │
└────┘

Default:
position = tile center

Allow rotation:
0°
90°
180°
270°

If an obstacle is larger than one tile, define its footprint.

7.15 Object footprint
Object definition:
ObstacleSmall
1 × 1

ObstacleWide
2 × 1

Barrier
3 × 1

When placing, the editor shows occupied cells.
Prevent invalid overlap where necessary.

7.16 Sign placement
Signs use same grid.
Example:
Slow Sign

tile = (15, 24)
rotation = 90°

Default orientation can optionally use nearby road direction later.
For now manual 90° rotation is enough.

7.17 Start signal
Same object system:
StartSignal

Placed on a tile.
It can have runtime state:
Red
Yellow
Green
Off

Later scenario logic controls it.

7.18 Trigger layer
Triggers are invisible logical regions.
Examples:
SlowZone
StartTrigger
FinishTrigger
SpeedGate
GenericEventTrigger

They use tiles too.

7.19 Trigger region
A slow zone can simply be:
selected tiles

Example:
S S S S
S S S S
S S S S

where S means the tile belongs to:
SlowZoneTrigger

No need to place invisible GameObjects manually.

7.20 Car overlap
At runtime:
car position
    ↓
WorldToGrid()
    ↓
current tile
    ↓
lookup trigger layer

For more accurate detection, sample vehicle footprint:
front-left
front-right
rear-left
rear-right
center

Then decide whether a trigger region has been entered.

7.21 Trigger enter/exit
Each trigger tracks:
wasInside
isInside

Then:
false → true
= Enter

true → false
= Exit

Publish:
TriggerEntered
TriggerExited

to the Step-1 event bus.

7.22 Generic trigger architecture
Avoid creating a unique MonoBehaviour for every course event.
Use:
TriggerInstance
├─ type
├─ region
└─ parameters

Types:
Start
Finish
SlowZone
Event

Then runtime trigger system interprets them.

7.23 Generic event trigger
This is your flexible event system.
Example:
{
  "type": "event",
  "region": {
    "x": 20,
    "z": 50,
    "width": 2,
    "height": 4
  },
  "eventId": "tunnel_entry"
}

When the car enters:
EventBus.Publish(
    CourseEvent("tunnel_entry")
)

Later:
scenario system
scoring
debug panel
can react.

7.24 Speed gate
A speed gate should be slightly different from a region.
Place it along a tile boundary.
Example:
┌────┬────┐
│    │    │
├────G────┤
│    │    │

Where:
G = gate line

Define:
Grid edge
+
orientation

rather than a large area.

7.25 Speed gate data
{
  "type": "speed_gate",
  "cellX": 20,
  "cellZ": 30,
  "edge": "north"
}

Runtime calculates a line segment across the road.

7.26 Gate crossing detection
Previous vehicle position:
P0

Current position:
P1

Check whether segment:
P0 → P1

crossed the gate.
This is better than checking whether the vehicle happened to overlap a tiny trigger during one frame.

7.27 Two-gate speed measurement
Example:
Gate A
    ↓
car
    ↓
Gate B

Record:
tA
tB

Known distance:
d

Then:
\[ v = \frac{d}{t_B - t_A} \]
This can feed the scoring system later.

7.32 Editing structures
For v1, keep editing simple.
For a tunnel/ramp:
move
resize
rotate
delete

Resize handles should snap in whole tiles.
No arbitrary centimeter resizing.

7.33 Moving structures
Dragging:
Tunnel 4 × 8

moves the entire footprint tile-by-tile.
This keeps everything aligned.

7.34 Object movement
Objects move from tile center to tile center.
Optionally later:
local offset

can be supported for unusual cases.
But don't add it now unless needed.

7.35 Undo/redo
All Step-7 actions go through the Step-6 runtime undo system:
Place structure
Delete structure
Resize structure
Move structure
Place object
Move object
Paint trigger
Delete trigger

Ctrl+Z must work in standalone build.

7.41 Unique IDs
Every structure/object/trigger gets an ID.
Example:
tunnel_01
ramp_01
slow_sign_02
speed_gate_a

Needed later for:
scoring
events
scenario control
debug logging
Don't rely on array index.

7.42 Auto-generated IDs
Editor can generate:
tunnel_001

7.43 Validation
Before saving:
Tunnel must occupy road tiles
Ramp must occupy road tiles
Obstacle placement must be within map bounds
Trigger region cannot be empty
IDs unique

Invalid items should be highlighted.

7.44 Tunnel validation
Example:
tunnel region contains:
32 tiles

road under tunnel:
30 tiles

Warn:
2 tunnel tiles do not contain road.

Allow override only if needed.

7.45 Ramp validation
Ramp requires:
continuous rectangular region

and:
road coverage across full ramp

Otherwise geometry becomes weird.
Reject invalid ramps initially.

7.46 Object collision validation
Prevent:
two large obstacles occupying the same tile
start signal inside tunnel wall
obvious impossible placements
But don't build a huge rule engine.
Simple occupancy checks are enough.
